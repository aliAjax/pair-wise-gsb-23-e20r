# hxwl-09 半导体洁净室巡检 — 离线采样回网合并

巡检员离线采样后回网，合并房间采样、层流台占用与批次放行单的业务沙盘（纯前端模拟，状态持久化到 localStorage）。

## 技术栈

React 19 + Vite 7 + TypeScript + CSS（无 UI 框架）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5109

规则引擎冒烟测试：

```bash
npx tsx scripts/smoke.ts
```

## 业务规则与落点

1. **合并三类数据**：回网后一次性合并房间采样、层流台占用登记、批次放行单（`src/domain.ts` 的 `attemptSync`）。
2. **层流台占用互斥**：同一层流台同一时段只能归一个房间；当班占用与离线批次互斥，待合并队列按批次号先到先得，互斥结果在「层流台占用」矩阵标红（`hoodConflict` / `occupancyView`）。
3. **采集时点与设备快照**：每条离线采样带 `collectedAt` 和设备快照（校准有效期、滤芯更换日期）；校准或滤芯维护登记后，引用旧快照的放行结论**立即失效、重算为需重采重算**，原始采样保留不删改，只打旧快照标记（`applyMaintenance` / `STALE_SNAPSHOT`）。
4. **同字段两边改过**：离线端与当班端同时修改同一字段时，两版并排保留，生成待办由下一班确认（「冲突与维护」页，`ensureNoteConflict` / `RESOLVE`）。
5. **失败单独重试、接收幂等**：B-2401 首次同步必失败，可单独重试；已接收批次重复合并被幂等忽略并写入审计（`DUPLICATE`）。
6. **放前阻断**：房间有未结异常、容量不足、粒子超洁净等级阈值、引用旧快照、层流台冲突均阻断放行；阻断对象（异常单号、容量、采样编号、占用归属）在批次卡片、「阻断与审计」页逐项列出。

## 建议演练路径

1. 点击「离线模式」切回网 → 合并全部：B-2401 首传失败，B-2402/B-2404 阻断，B-2403 自动放行。
2. 在 B-2401 卡片上点「单独重试」，接收后因 LF-01 A 段已归属封装间而阻断。
3. 到「冲突与维护」处理 B-2401 / B-2404 的放行备注两版。
4. 点「登记滤芯维护（LF-03）」：B-2403 与当班 B-2388 的放行结论即时失效，采样仍在；待合并批次重算增加旧快照阻断。
5. 「阻断与审计」页查看阻断对象汇总与全程留痕；页头可重置演练数据。

## 目录

- `src/types.ts` — 领域模型
- `src/domain.ts` — 种子数据、规则引擎（合并/阻断/维护失效/审计）与 reducer
- `src/store.ts` — useReducer + localStorage 持久化
- `src/components/` — 批次、占用矩阵、冲突与维护、审计四个面板
- `scripts/smoke.ts` — 35 条规则断言
